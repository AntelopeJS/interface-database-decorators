# Define tables and work with models

## Overview

Use `@antelopejs/interface-database-decorators` to describe tables with TypeScript classes and work with converted records through models. It builds on AQL (`@antelopejs/interface-database`) and adds field modifiers and API model injection.

## From a table class to a stored record

1. **Describe the table.** Extend `Table`, declare fields and indexes, and register the class with `@RegisterTable("users", "myapp")`. See [table definitions](./2.table-definitions.md).
2. **Bind the schema.** Import the table declarations, then call `await RegisterSchema("myapp")` from their declaring module. This requires a configured database provider and can provision tables and insert fixtures; it is not a read-only metadata operation.
3. **Create the model.** Use `BasicDataModel(User)` and a `SchemaInstance`, or `GetModel` after the table has been bound. See [data models](./4.data-models.md).
4. **Write and read through the model.** Model operations apply conversion and modifier events. Use `model.table` when you need to compose an AQL query yourself.

Keep schema IDs and instance IDs distinct: `myapp` identifies the table definitions; an instance ID selects the database instance used by a model. A table class without a schema binding cannot be resolved by `GetModel`.

## Choose the layer for your task

| Task                                | Layer                                               | Important boundary                                               |
| ----------------------------------- | --------------------------------------------------- | ---------------------------------------------------------------- |
| Describe storage fields and indexes | [Table definitions](./2.table-definitions.md)       | Declaring a class is separate from registering its schema.       |
| Encrypt, hash, or localize fields   | [Table modifiers](./3.table-modifiers.md)           | Conversion events determine when transformations run.            |
| Read or write converted records     | [Data models](./4.data-models.md)                   | Reads return converted records, not chainable queries.           |
| Select a model in an HTTP request   | [Parameter decoration](./5.parameter-decoration.md) | The instance ID selects a binding; it does not authorize access. |

Start without modifiers until the schema and model work together. Add validation explicitly: string-token `@Field` declarations describe storage, while codec validation requires codecs and the model's validation options.

## Dependencies

This package depends on the following:

- [**@antelopejs/interface-database**](https://github.com/AntelopeJS/interface-database) - The underlying database query interface (AQL)
- [**@antelopejs/interface-api**](https://github.com/AntelopeJS/interface-api) - API controller integration for parameter decoration
- [**@antelopejs/interface-core**](https://github.com/AntelopeJS/interface-core) - Core decorator utilities
- [**reflect-metadata**](https://www.npmjs.com/package/reflect-metadata) - Metadata reflection for TypeScript decorators
- [**randomstring**](https://www.npmjs.com/package/randomstring) - Random string generation for hash salts
